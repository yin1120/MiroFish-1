全景流程圖 13 大核心步驟詳細解釋手冊

步驟 1：劇本正則與格式校驗 (Parser_Regex)

嚴格固定三大標記：(A) 關主規則手冊、(B) 關主核心真相、(C) 角色客觀劇本庫。正則解析若發現結構缺漏立即觸發 Halt_Format 報錯中止，保證解析一致性。

步驟 2：圖譜先行規模一致性校驗 (Graph_Check)

公開背景先行送入 Zep KG 生成純淨圖譜。機制核心向 Zep 查詢角色節點總數是否剛好等於 $N$ 人，檢查關係邊連通性，排查幽靈角色與無名斷裂點；私密專區寫入 agent_private_assets（通用 metadata JSON 容器）；核心真相寫入 GM Truth DB，落實三庫物理隔離。

步驟 3：功能優先動態開版演繹與板規契約派發 (Deduction_Engine)

  • 功能優先 (Function-First)：依據劇本玩法提煉公聊辯論、隔音密會、手牌展示、謎題認領、暗投等互動需求；5 大看板能力原型庫作為 Few-Shot Prompt 基準。
  • 能見度與進場限制：公開看板 (全員可見)、一人私人看板 (專屬道具庫/私密小本本，限本人+GM)、多人私聊看板 (限定 members 名單)。
  • 動態板規 (BoardPolicy)：合成 allowed_actions 動作清單、chat/read-only 發言權限、3 種生命週期 (permanent 永久、cyclical 週期輪次、one_shot 單次)。
  • 看板中心化可見性：看板自帶受眾邊界，發布至該看板直接決定受眾，無冗餘計算。

步驟 4 & 5：通訊掛載與關主開場主持 (GM_Round0)

通訊層掛載契約看板；關主 Round 0 執行 ManualAction 宣讀世界觀、勝負目標、時序流程與中立裁判職責，強制打上 SYSTEM_GROUND_TRUTH 置頂大廳，作為全場 100% 絕對信任真理。

步驟 6 & 7：動態時序計算器與關主每輪引導廣播 (GM_Preturn_Guide)

破除死板固定順序，每輪開場依規則重算發言順序清單（如上輪最落後者先動）；輪到每位 Agent 前，關主率先主持點名引導：「輪到 Agent X，本輪依據規則可前往哪些看板、可執行哪些合法動作」，確立合法思考邊界。

步驟 8：機制發言權威審查 (Perm_Check)

機制審查 Agent 狀態：處於 DISABLED 失能者直接進入禁言休眠模式 (Mute Sleep: 0 Token 消耗、跳過發言、背景接收事實)；狀態正常者放行行動。

步驟 9：Agent 四維感知與心智審議 (Agent_Mind_Process)

  • 維度 1：主觀心智筆記：非零和猜忌原則（防線 1），認為在場所有人都不完全可信，記錄矛盾與 1~10 分懷疑評級。
  • 維度 2：個人私有歷程與資產：曾參與過之私聊隔音歷史、個人專屬道具、不可告人秘密。
  • 維度 3：公共看板歷史：大廳公共對話流、手牌明牌、機關任務累計進度。
  • 維度 4：客觀真理與 Zep KG：關主 100% 絕對信任真理公告與 Zep 客觀人設世界觀。
  • 決策輸出四元組：刷新心智筆記後輸出 (target_board, thought, speech, action)。

步驟 10：機制核心五大通用守門法則審查 (Arbiter_Five_Guardrails)

審查 ①權限資格與動作合規、②資產所有權與約束 (consumed、共有道具單輪限一人代表)、③線索探索與 unique 鎖定、④強制作業與階段卡點守衛、⑤勝負終止與安全熔斷。違規強制攔截 Rollback，合規放行發布。

步驟 11：看板中心化發布與動態穿插 (Board_Centric_Publish)

動作直接發布至 target_board，公聊推進主幹，私聊、專屬道具發動、物證公開、任務答題與暗投動態穿插其間。

步驟 12 & 13：通用事件響應、勝負熔斷與終局復盤報告

事件引擎捕獲狀態變更，關主即興主持與空投物證；若達成提前勝利立即熔斷中斷輪次循環 (Break Loop)；終局公布作案真相、審計個人目標、依劇本規則結算分數（無分數規則不硬給分），前端渲染 SimulationReportView.tsx 復盤報告。
