# 通用劇本殺多智能體模擬系統 (Generic LARP Multi-Agent System)
# 功能需求規格書 (Functional Requirements Document - FRD)

---

## 1. 系統願景與目標 (Vision & Scope)
本系統旨在構建一套**通用型劇本殺 / 社交推理解謎與陣營博弈多智能體模擬平台**。系統可**通用相容任何題材之劇本**（包含古典謀殺之謎、陣營狼人殺、機關搜證、科幻與商戰本等）。本系統的核心基石為**「最高權限遊戲機制核心 (The Arbiter Mechanism Engine)」**：
- **機制擁有最高主權**：整個遊戲的規則、流程進程、狀態約束完全由機制核心裁決；玩家能否說話、能否使用道具、能否投票皆由機制嚴格審查；
- **編排本局關主與看板**：機制核心在載入劇本後，以預置的【通用看板能力庫】與【關主職責元規範】為依據，自主決定本局啟用的看板清單，並為關主 Agent 生成本局專屬的主持與 ManualAction 規範；
- **劇本自帶題庫與混合驅動**：任務題目由劇本手冊自帶提供；關主注入物證採混合驅動（手冊建議輪次 + 關主自主評估現場火候成熟發布）；
- **嚴格視角隔離與資產管理**：純淨客觀知識圖譜、單一資料表 Key 區分資產庫（道具/秘密/任務）、無記名暗投、失能禁言休眠限制（能看不能說）、陣營積分與提前結束機制；
- **前後端通訊原生相容**：沿用 MiroFish 原生 REST API 輪詢機制（每 2~3 秒拉取最新動作），關主廣播、題目、分數與失能狀態皆以 `CREATE_POST` 貼文形式無縫廣播。

- **後端環境**：Python (FastAPI / 模組化推理引擎)
- **前端環境**：React (視覺化看板、即時圓桌、私聊視窗、任務活動看板、純文字心智筆記卡片)
- **核心設計哲學**：拒絕全知視角（Fog of War 戰爭迷霧）、機制最高權限（Arbiter Control）、非對稱資訊博弈。

## 2. 角色與權限定義 (Roles & Permissions)

| 角色 / 中樞 | 定位 | 認知邊界與權限 |
| :--- | :--- | :--- |
| **最高機制核心<br/>(Mechanism Engine)** | 世界底層物理法則、最高法官與編排中樞 | **全場最高權限**。讀取劇本手冊，對照看板能力庫與關主職責，編排本局看板與流程；嚴格約束玩家權限（判定失能、阻斷違規發言與道具使用）；監控勝負條件與觸發器。 |

| **人類研究員<br/>(Researcher / User)** | 模擬發起與觀測者 | 上傳單一劇本檔案、控制推演流程、觀測玩家心智與私聊、亦可介入機制核心觸發 ManualAction、檢視第四階段時間序復盤報告。 |

## 3. 功能模組詳細規格 (Functional Requirements)

### 模組 1：最高機制核心之劇本攝入與本局編排 (Mechanism Orchestration)
- **需求代碼**：`FRD-01`
- **架構地位**：遊戲機制核心（Mechanism Engine）坐鎮後端最高權力層。
- **輸入依據**：
  1. **輸入一：單一劇本檔案 (Markdown)**：
     - 【關主規則手冊】：包含基本配置、遊戲機制指南、劇本自帶題庫清單。
     - 【關主核心真相】：全局案件真相（真凶身分、手法、伏筆），僅 GM 可讀。
     - 【角色客觀劇本庫】：各角色公開區與私密專區。
  2. **輸入二：後端預置通用看板能力庫 (Board Capabilities Library)**：包含公共對話板、公共手牌板、任務活動板、彈性私聊/陣營道具工作區、關主私密投票之能力定義。
  3. **輸入三：關主職責元規範 (GM Meta-Prompt Guidelines)**：包含關主的主持準則、裁判職責與 ManualAction 工具集。
- **機制核心之編排決策產出 (Session Contract)**：
  - 機制核心讀取劇本後，對照輸入二與三，自動生成**本局執行契約**：
    1. **Agent 人數強制校驗**：核對生成的玩家數量與身分名單，不符則終止。
    2. **本局功能開關清單 (Feature Flags)**：依劇本規則判定是否開啟失能機制 (`enable_disabled_status`)、計分系統 (`enable_scoring_system`)、道具手牌 (`enable_card_revealing`) 等。
    3. **本局啟用看板清單**：依功能開關精確輸出欲掛載至系統的看板清單。
    4. **本局關主執行規範**：定義關主開場規範、題庫抽取規則、物證注入指導（混合驅動）、暗投時機。
    5. **玩家約束規則表**：定義失能禁言條件、道具使用白名單、發言權限狀態。

### 模組 2：機制嚴格約束與狀態機控制 (Strict Mechanism Constraints)
- **需求代碼**：`FRD-02`
- **權限約束原則**：玩家的一切主動動作**必須先過機制核心審查，不可自由越權**。
- **動作約束矩陣**：
  1. **機制發言權威裁決與失能禁言 (Speaking Rights & Mute Mode)**：
     - **發言權審查層**：輪到玩家時，由機制核心主動裁決其是否具備發言權 (`SPEAKING_RIGHT`)。若劇本未啟用失能規則，機制直接核准發言權 (`GRANTED`)；若啟用且玩家處於 `DISABLED`，機制判定剝奪發言權 (`REVOKED`)，強制進入「禁言休眠模式 (Mute Sleep)」，調度器跳過發言（零 Token 消耗），背景仍接收公共事實。
  2. **純發文形式之道具與出牌約束 (Post-Driven Item Usage & Reveal)**：
     - **全流程發文驅動，拒絕 UI 點擊**：所有道具使用、技能發動與線索亮牌**一律以發文形式 (CREATE_POST / ACTION_POST) 執行**。玩家在聊天視窗中輸出具備結構化語義的發文；機制核心校驗 `agent_private_assets` 持有權與可用性。
     - 若為公開出牌，原地 UPDATE `visibility='public'` 並自動於公共手牌看板同步展示；若為私密使用，僅在私密房間/後端留痕，不對外洩露。
  3. **彈性私聊/陣營工作區與私密投票穿插架構**：
     - **不限人數的彈性私聊與陣營沙盒**：私聊不侷限於雙人，支援指定多名玩家之「陣營私密頻道」（如狼人黑夜全員私密討論室、偽裝者密談室或 2~N 人密謀房間），隔音且對外保持戰爭迷霧。
     - **同聊天室窗發文一體化 (對話與道具全發文)**：關主在聊天室一端，玩家/陣營在另一端。玩家在有限輪次或時限內透過發文相互討論，最終在同一視窗中**以發文形式宣告使用道具/發動技能**（例如狼人發文：`【發動技能】狼牙夜襲 ➔ 目標: 3 號`）。關主確認合規後，亦在同聊天室發文回覆確認（如：`【關主確認】已鎖定襲擊目標為 3 號，狼人請閉眼`）。
     - **對 GM 點對點私密發文投票**：投票階段玩家不公開表態，而是直接向關主 (GM) / 機制核心私密發文提交選票；關主在後端統整票數與裁決結果後，統一以高權限 `CREATE_POST` 貼文於公共對話板公示最終結果。
  4. **失能與復原控制**：機制核心掌握失能計時器，經指定輪次或特定救援行動（如維生系統）方可解除。

### 模組 3：私密資產儲存位置與 Key 權限隔離機制 (Secret Storage & Key Isolation)
- **需求代碼**：`FRD-03`
- **單一資料表存儲**：
  - 角色劇本中【私密專區】所屬的**道具、秘密、個人任務**，在推演資料庫（`simulation.db`）中，**全部集中儲存在同一張 SQLite 資料表 `agent_private_assets` 裡**，絕不拆分成零散多檔。
  - 欄位：`id`, `agent_id`, `category` (item | secret | objective), `title`, `content`, `visibility` (private | public), `status`。
- **隔離與流轉**：
  - **知識圖譜 (KG) 零污染**：圖譜完全不讀取此表，只解析公開背景故事，保證客觀圖譜絕對純淨。
  - **個人 Prompt 注入**：以 `WHERE agent_id = ? AND visibility = 'private'` 查詢注入個人私有欄。
  - **出牌即時轉公開**：出牌時僅更新 `visibility = 'public'`，公共手牌看板即可直接顯示。

### 模組 4：通用看板能力矩陣 (Universal Board Capabilities)
- **需求代碼**：`FRD-04`
- 機制核心可調用的 5 大通用看板：
  1. **公共時間序對話看板 (Public Stream Board)**：公開發言、GM 廣播、系統通知。
  2. **公共手牌/道具看板 (Public Card Board)**：展示全場已亮牌之公開道具與實體線索。
  3. **任務活動與分數看板 (Task & Score Board)**：關主發布劇本題庫題目、玩家認領答題、陣營分數即時進度條。
  4. **彈性私聊與陣營道具沙盒 (Flexible Whisper & Faction Sandbox)**：支援 2~N 人彈性密談與陣營私密頻道（如狼人黑夜私聊、結盟密會），並深度整合「私聊發言 + 私密道具/技能暗中發動」一體化功能。
  5. **關主私密投票機制 (Private Ballot to GM)**：玩家點對點向關主/機制核心提交加密選票（如白天放逐、結案指認），關主統整票數後以 `CREATE_POST` 貼文於公共大廳公告票決結果。

### 模組 5：關主物證混合驅動注入與事件靈活響應 (Mixed-Trigger & Dynamic GM Response)
- **需求代碼**：`FRD-05`
- **關主物證注入（混合驅動模式）**：
  - 劇本手冊給予建議注入輪次（如第 3 輪）；
  - 關主 LLM 於該輪發言結束後，自主評估現場討論熱度與矛盾激烈程度，**判定「時機成熟」方執行 ManualAction 注入物證**，兼具導向性與靈活性。
- **通用動態事件響應**：
  - 機制捕獲事件（如答題成功、機關破壞）後，**喚醒關主 LLM，由關主結合當前局勢靈活輸出主持詞與處置動作**（加扣分/給道具/發布警報/即興調侃），拒絕死板硬編碼廣播。

### 模組 6：Profile 玩家個性生成（5 大博弈維度）(Player Meta-Persona Generation)
- **需求代碼**：`FRD-06`
- **演員與角色解耦**：劇本客觀事實寫死（零幻覺），Profile 階段生成操控該角色的「玩家遊玩風格」：
  1. 勝負欲與攻擊性 (Competitiveness)
  2. 誠實度與抗壓防線 (Honesty & Panic Baseline)
  3. 社交支配力 (Social Dominance)
  4. 溝通與私聊熱情 (Whisper Affinity)
  5. 邏輯細緻度 (Deductive Rigor)

---

### 模組 7：多維感知依據與半結構化純文字心智筆記 (Multi-Source Perception & Notes)
- **需求代碼**：`FRD-07`
- **發言前三大參考依據**：輪到 Agent 發言前，系統完整注入：
  1. **各看板歷史紀錄**：時間序對話流、任務題目進度、關主客觀物證；
  2. **主觀認知表格**：前輪心智筆記、對全場玩家的矛盾與疑點；
  3. **私密手牌資產**：暗牌道具、不可告人秘密、私有任務與全場公開明牌。
- **純文字心智筆記刷新**：三方交叉比對後，針對在場**所有其餘玩家**生成/刷新第一人稱心智筆記：
  `【[角色名] 的第一人稱心智筆記 (輪次 [R])】：- 針對【目標玩家 A】：• 觀察與矛盾點 • 當前評估與態度 • 下一步策略`。

### 模組 8：私密向 GM 投票、失能休眠與提前結束 (Private Ballot to GM, Sleeping & Early Victory)
- **需求代碼**：`FRD-08`
- **向關主私密投票 (Private Ballot to GM)**：各玩家於投票節點點對點向關主提交選票，選票明細對其餘玩家完全隱蔽；關主/機制核心匯總計票後，統一在公共對話流發布票決通告。
- **失能禁言休眠限制**：失能者在輪詢時**直接跳過喚醒，不呼叫 LLM，不消耗 Token**；背景持續接收公聊 Observation；GM 守門員實施發言與動作阻斷。
- **陣營積分與提前結束**：陣營達到目標分數（如 100 分）時，機制核心**立刻中斷常規輪次循環 (Break Turn Loop)**，關主宣告提前勝利，直接跳轉第四階段復盤報告。

---

### 模組 9：前後端通訊架構：原生 REST Polling 相容機制 (Native Polling Compatibility)
- **需求代碼**：`FRD-09`
- 前端 React 完全繼承 MiroFish 原生之 **定時增量輪詢機制 (Timer Polling)**：
  - 前端每 2~3 秒呼叫 `GET /api/simulation/{id}/run-status/detail`，拉取伺服器最新動作清單 `all_actions`。
  - **發題、戰況報分、失能通報皆作為高權限 `CREATE_POST` 貼文廣播**：由後端寫入動作隊列，前端定時輪詢拉取後直接渲染於對話與活動看板上，架構穩定，無需引入複雜 WebSocket。
